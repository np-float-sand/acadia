## What Was Done This Session

### Goal
PJM T&D utilities were actively destroying alpha because LMP/GSI signals don't apply to rate-regulated companies. The fix: make the factor model business-model-aware.

### Solution
Three architectures tested:
1. **Hard switch** (winner): `pass_through < 0.5` → ICR signal; `pass_through >= 0.5` → stress beta
2. **Revenue mix**: blend by `pass_through` coefficient
3. **Dual-track**: same blend but z-scored within peer subgroups

Hard switch wins because the binary routing is cleaner than blending noisy ICR data into a well-calibrated stress beta signal.

### Root cause of PJM problem (confirmed)
Rate-regulated T&D utilities earn revenue set by state rate cases, not LMP. The stress beta has zero mechanistic link to their earnings. Adding ICR as their primary signal captures refinancing risk during rate stress events instead.

### Key Analytical Finding: ICR ≠ Data Centers
The hard-switch architecture routes PJM T&D utilities to an ICR signal (financial fragility). This does NOT capture data center load growth. ICR identifies which utilities are fragile under rate stress; it says nothing about which utilities benefit from data center demand.

Key distinction:
- **D (Dominion)**: Massive data center territory (Northern Virginia #1 global DC market) → ICR reflects debt load from nuclear build, NOT DC growth
- **PEG (PSEG)**: NJ corridor (Amazon, Google) → ICR reflects financial leverage, not DC positioning
- A utility with poor ICR but enormous DC load growth in its territory would incorrectly score as a short

### Phase 2 Signal Decision
Data center / interconnection queue signal is the priority regulated-utility signal to build next. ICR is placeholder. Data sources:
- **PJM interconnection queue**: public downloadable, shows queued large-load requests by zone — directly maps to D/PEG/EXC service territories
- **EIA-861**: annual survey, load by customer class (industrial/large commercial) — tracks realized load growth
